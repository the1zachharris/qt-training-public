# Neighborhood Pizza: WCAG 2.2 Accessibility Report

**Date:** 2026-11-10 · **Branch tested:** `ZH-pass1` @ `55b8310` (after the worker's M1–M4 / L1–L5 fixes) · **Fix branch:** `ZH-wcag`
**Browser:** Microsoft Edge (Playwright `msedge` channel), headless · **Theme:** light only (dark mode was out of scope for this pass)
**Status:** DRAFT for review. Severities and fixes are recommendations. Automated testing cannot prove conformance; a QT employee must make the final call, ideally after a manual screen-reader pass (NVDA or Narrator).

---

## 1. Standard used

**WCAG 2.2, Level A and AA** is the current W3C Recommendation ([w3.org/TR/WCAG22](https://www.w3.org/TR/WCAG22/)). WCAG 3.0 is still a Working Draft ([w3.org/TR/wcag-3.0](https://www.w3.org/TR/wcag-3.0/), latest draft March 2026) and is not meant for conformance claims yet, so it was not used.

## 2. How it was tested

New suite: `e2e/accessibility/wcag.spec.ts` with `e2e/playwright.accessibility.config.ts`. It starts its own API and UI on ports 5319 / 5376 with a throwaway database.

- **Automated rules:** [axe-core](https://github.com/dequelabs/axe-core) (`@axe-core/playwright`) with every WCAG 2.0/2.1/2.2 A and AA tag, on 12 screen states: menu, navigation drawer open, pizza builder dialog, "added" toast, empty cart, cart with pizzas, checkout, checkout name error, order confirmation, order not found, kitchen (New and Ready orders), and page not found.
- **Targeted checks for what axe cannot judge:**
  - a full order placed with the keyboard only (2.1.1)
  - every Tab and Shift+Tab stop compared in screenshots, focused against unfocused (2.4.7), and tested for being hidden behind the fixed header (2.4.11)
  - 320px and 640px widths (1.4.10, and 1.4.4 at 200% zoom)
  - WCAG text-spacing override and 200% root text size (1.4.12, 1.4.4)
  - border and icon contrast of controls (1.4.11)
  - names, roles, and states in the accessibility tree (4.1.2, 1.3.1)
  - live regions for messages (4.1.3)
  - tooltip behavior (1.4.13)
  - toast timing (2.2.1)
  - landmarks and heading structure

```bash
cd e2e
npx playwright test -c playwright.accessibility.config.ts
npx playwright show-report playwright-report-accessibility
```

Raw results for every check are written to `e2e/test-results-accessibility/_findings/*.json` (not committed).

## 4. Findings

Severity guide:
- **High:** a WCAG A/AA failure that blocks or seriously hinders a group of users on a main task.
- **Medium:** a clear A/AA failure with a workaround.
- **Low:** a borderline or best-practice item.

**Status:** "Fixed" means changed on `ZH-wcag` and re-tested with the suite (section 4.4). Nothing is merged into `ZH-pass1` yet.

**About the 38 failures in the first run:** some of them were bugs in my new checks, not the app. These were fixed before the findings above were written up:
- The 200% text check applied the scaling twice.
- The reflow and text-spacing checks counted hidden MudBlazor tooltips and click ripples as content.
- Two checks used locators that did not match the app.
- One test reused a browser tab, so the cart carried over between states.

All findings in 4.1–4.3 were confirmed against the app itself, in screenshots or the rendered DOM.

**Test changes that came with the fixes:**
- Locators now follow the new accessible names, for example "Add Cheese" and "Remove The Works, Large (14")": `tests/helpers.ts`, `tests/ordering.spec.ts`, `exploratory/ui.spec.ts`.
- The builder price is now plain text instead of a heading, so `builderPrice` finds it by class.
- One exploratory race fix: "New column is oldest first" read the kitchen cards before the board loaded. It now waits for the orders, and the ordering check is unchanged.
- No check was loosened.

## 5. What passed

Results from the axe-core scan and the targeted checks, run before and after the fixes:

- **Keyboard only (2.1.1, 2.1.2):** a full order works with the keyboard alone: Start Building, arrow keys for size, Space for a topping, Add to Order, cart, Continue, name, Enter. No keyboard traps.
- **Dialog:**
  - Focus moves into the builder dialog and stays there.
  - Escape closes it, and focus returns to "Start Building".
  - The dialog has `aria-modal` and is named by its title.
  - Topping chips expose their pressed state.
- **Focus Visible (2.4.7):** every Tab and Shift+Tab stop on the menu, dialog, cart, checkout, and kitchen shows a visible change when focused, checked in screenshots.
- **Focus after navigation (2.4.3):** after each page change, focus moves to the new page's h1 (worker fix M4).
- **Reflow (1.4.10):** no sideways scrolling at 320px or 640px on any page, including the cart table and the kitchen board (worker fix M1).
- **Target Size (2.5.8, new in 2.2):** no axe violations.
- **Page Titled (2.4.2) and Language of Page (3.1.1):** every page has its own title, and `lang="en"` is set.
- **Checkout name field (3.3.1, 3.3.2):**
  - It is labeled, `required`, and `aria-invalid` when blank.
  - It is linked to its "Required" message with `aria-describedby`.
  - The helper text explains what the name is for.
- **The "added" toast (4.1.3):** it is announced (`role=alert`, polite) and pauses while hovered.
- **Quantity field:** a named spinbutton with increment and decrement buttons.
- **Not applicable:** 2.5.7 Dragging, 3.3.7 Redundant Entry, 3.3.8 Accessible Authentication, 1.2.x media, 1.4.2 audio.

## 6. Not covered and recommended next steps

- **Dark mode** was skipped on request. MudBlazor's dark palette still uses the old Success, Error, and Warning colors, which failed in light mode, so expect similar contrast failures there.
- **Screen-reader pass:** automated checks read the accessibility tree but do not hear it. Run one order end to end with NVDA + Edge and with Narrator.
- **Zoom in the real browser:** 200% and 400% were simulated (root font size and a narrow viewport). Spot-check with Ctrl + in Edge.
- **Windows High Contrast / forced colors** was not tested.
- **3.3.7 Redundant Entry, 3.3.8 Accessible Authentication, 2.5.7 Dragging:** not applicable today. There is no sign-in, no repeated entry, and no dragging. Revisit when the kitchen gets staff sign-in (earlier report D1).
